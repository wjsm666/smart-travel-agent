## 本轮实现

- `frontend/src/App.vue` 接入 B 的 `catalog-loaded` 和 `plan-generated` 事件，将景点及草案交给 A 的 `TripWorkspace.vue`。已有草案未保存时，新结果先提示替换；取消保留本地修改。
- `frontend/src/types/contracts.ts` 对齐后端和 API 的 snake_case 字段，保留可空票价、可空预算判断和每日说明。`api/client.ts` 统一读取可读错误，无法解析时显示通用提示，支持取消请求。
- `modules/trips/useDraftEditor.ts` 将服务端景点快照转换成独立的分日 ID 输入，不回传费用或状态，不修改父组件对象。增删/重排清除当日旧说明，跨日移动清除来源与目标日旧说明；支持重新填写说明。
- 每次编辑立即使旧费用结果和校验请求失效。取消请求之外同时检查草案版本及请求编号，即使旧响应仍到达，也不能覆盖新编辑、错误或新请求的加载状态。重复点击校验不会重复发请求。
- 费用、预算提示及业务限制以 `POST /api/plans/validate` 返回为准，不新增前端费用引擎。未知门票显示“待确认”；`over_budget=null` 显示“预算待确认”。调整后隐藏旧汇总，失败明确显示错误。页面说明来源、参考性质和刷新丢失边界，模型/用户说明按文本渲染。

HTTP 契约、原业务规则、B 的 `modules/planning/`、后端代码和实验材料均未修改。没有新增数据库、账号、地图、Agent 或工具。保存/历史/删除不放置假按钮；当前草案只在页面内存中。

## 启动与验证

实际前端环境为 Node 24.16.0、pnpm 11.25.0，后端沿用已有 Python 3.13.18 环境及锁文件。前端依赖锁定 Vue 3.5.44、Element Plus 2.14.7、Vite 8.3.5、TypeScript 5.9.3、vue-tsc 3.3.14；沿用 B 已验证的兼容组合。开发服务均只绑定本机。完整启动命令见 [README](../README.md)。

在 `frontend` 目录：

```powershell
pnpm install --frozen-lockfile
pnpm dev
```

另一终端在 `backend` 目录：

```powershell
uv sync --locked
uv run --locked uvicorn app.main:app --host 127.0.0.1 --port 8000
```
