# 后端开发规则

遵循根 `AGENTS.md`。使用 Python、FastAPI、Pydantic 2，B 已初始化并锁定后端依赖。规则生成与统一校验已接入；保存管理、前端主工程及真实模型联调尚未完成。

B 维护 `app/main.py`、`app/contracts.py`、`app/errors.py`、配置和后端依赖；A 维护 `app/itineraries/`；B 维护 `app/catalog/`、`app/planning/` 和景点样例。接口签名见 `docs/architecture.md`。

通用 Pydantic 模型只在 `contracts.py` 定义，避免两个模块分别定义不兼容的同名请求。共享模块不能反向依赖业务模块。费用和草案规则只在 A 的统一校验服务计算；B 生成的候选草案必须经过该服务。

HTTP 路由只接收请求和调用服务，不堆积模型提示词或业务计算。LangChain 仅用于规划模块，不渗入普通行程管理。不得引入数据库或额外工具替代既定文件存储与只读景点工具。

保存前再次校验，不信任客户端和模型提交的费用。保存记录使用服务端生成的 ID、时间与景点快照；文件缺失视为空集合，文件损坏必须报错而非覆盖。仅支持单进程本地使用，保护单进程内的读改写，采用临时文件替换避免中断留下半个 JSON 文件。

模型地址和密钥只在后端配置。只读景点工具不得使用模型指定的任意文件路径；普通查询与工具共用景点服务。输入、输出、工具参数按文档验证，错误做统一脱敏。

测试使用少量独立样例及临时目录，不依赖真实用户行程。真实模型联调由 B 单独记录；普通后端测试不消耗真实 API 配额。运行前确认实际依赖、脚本和模块路径，再报告命令与结果。
