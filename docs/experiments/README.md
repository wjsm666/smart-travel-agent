# 软件工程实验交付

实验按教师顺序和要求提交，不等待整个原型。图表数量、提交格式和实验七是否沿用自选题目，以教师要求为准；以下主责按实验组织，不代表一人包办所有业务分析。

| 实验 | 主整理 | 主要内容 | 另一人的参与方式 |
| --- | --- | --- | --- |
| 一 | A | 系统目标、F01–F06 功能简述、工具情况和报告 | B 核对规划和景点模块需求 |
| 二 | B | 参与者、用例图、用例关系及叙述 | A 提供行程操作与异常，检查一致性 |
| 三 | A | 识别类、属性、操作和关系，形成类图 | B 核对景点、规划服务与接口 |
| 四 | B | 需求输入、生成、调整与保存等活动流程 | A 核对校验和保存路径 |
| 五 | A | 重要业务对象状态与转换，完善相关类图 | B 检查与生成流程的对应 |
| 六 | B | 生成和保存等用例的对象交互与时序 | A 提供行程服务顺序并检查 |
| 七 | A 汇总，B 检查 | 双方各自整合本模块 CIM/PIM、用例和 UML，A 整理报告，B 核对模型与演示证据 | 不重复重画；修改已有模型并同步文字 |

A/B 的开发模块主责见根 README。报告主责交替安排，综合部分按各自模块补齐，避免把每张图拆成两个人轮流编辑。

按需创建 `experiment-01/` 至 `experiment-07/`，保留模型源文件、可读导出图和报告。不要在尚未完成时提交假截图或把空目录当成果。个人信息按提交用途处理，不将不必要的学号、姓名和教师签名放进公开仓库。

实验八 SVN 是指导书另列练习，按教师安排单独处理，不擅自并入前七次。当前文档建立不代表任何一次课程报告已经完成。
