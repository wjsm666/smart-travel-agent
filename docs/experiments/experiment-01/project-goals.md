# 汕头智能旅游系统目标与边界

智能旅游行程规划与管理系统面向计划到广东省汕头市游玩的普通用户，旨在减少分散查找景点、手工分配游玩日期和反复估算门票开支的负担。系统以少量本地预置资料作为规划依据，把查询景点、填写需求、生成分日草案、人工调整、确认保存与查看连接起来，使用户能够理解并掌握自己的安排。当前实验一完成需求分析，不表示原型已经实现。

系统拟达到以下五项目标：

1. 提供汕头景点资料查询，展示名称、类别、简介与参考门票，支持按关键词和类别筛选。后续原型建议整理 8–10 条示例景点，逐条检查来源与费用口径；本次不声称数据已录入。
2. 以汕头为固定目的地，接收 1–5 天的旅游天数、可选兴趣偏好及非负整数门票预算。对不合法输入给出明确提示，避免无效需求进入规划过程。
3. 根据预置景点与需求生成按天划分的草案，每天最多两个景点，全程不重复。规则推荐构成基础方案，单 Agent 作为后续可选方式；数据不足时提示空白日期，不编造景点或保证路线最优。
4. 展示分日门票和总门票估算，允许用户增加、移除或移动草案中的景点，并在变更后重新校验。超过预算时明确提醒，由用户决定继续调整或接受；估算仅含本地参考门票，不含交通、餐饮和住宿，也不保证实时准确。
5. 只有用户确认后才保存当前合法行程，支持查看保存记录，使规划结果能够继续使用。管理员仅作为景点基础资料维护的分析角色，最小原型可直接维护数据文件，不建设复杂后台或账户权限系统。

本阶段限定汕头单城与本地演示，不纳入多城市推荐、实时地图导航、天气交通、联网爬虫、支付预订、多 Agent、RAG、完整部署及数据库平台。后续用例与实现应围绕上述可核对目标展开，避免扩大本次实验范围。
