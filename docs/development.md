# 开发顺序与启动任务

本版按实验和模块推进，无日历工期承诺。应用开发状态目前均为未开始；本文件列的是目标与检查点。

## 1. 阶段与完成边界

| 阶段 | A 的完整任务 | B 的完整任务 | 进入下一阶段的条件 |
| --- | --- | --- | --- |
| D0 工程与契约 | 初始化前端、公共类型和客户端，准备接入两个业务组件的页面 | 初始化后端、公共模型/配置/错误、健康检查、景点服务与样例 | 双方各自可启动最小工程；类型、模型和示例与 api.md 一致；这一步完成后不再独立猜字段 |
| D1 模块并行 | 完成行程模块前后端、规则推荐、统一校验、费用、保存/查看/删除及测试 | 完成规划模块前后端、景点浏览、生成入口、单 Agent 工具和脱敏错误测试 | A 可用固定合法草案及景点服务独立验收；B 可用接口替身独立验收，尚未联通不称整体验收通过 |
| D2 连接与验证 | 接入 B 前端组件和响应，验证规则闭环及编辑保存 | 注册 A 行程路由，接入 A 的规则和校验服务，验证真实 Agent | 契约无需改名即可互通，离线规则闭环可用；有凭据时完成真实 Agent 联调 |
| D3 课程整理 | 完成主责实验和综合报告整理 | 完成主责实验和综合演示检查 | 教师要求覆盖、模型一致、实现与设计范围如实标注 |

每位成员完整负责自己的模块，不需要先做完所有普通业务才允许 B 调试 Agent。D0 的共享模型与目录完成后可并行；测试替身只用于边界检查，生产代码不保留两套服务。

## 2. 实施检查点

- D0 不安装未经实际需要的数据库、部署或可视化组件；A/B 各自记录真实启动命令、版本、锁文件和验证结果。
- A 的统一校验和规则服务使用 B 的景点出口；B 的生成入口使用 A 的服务，不能各写一套费用或重复 ID 规则。
- 每次实验按教师要求及时提交，不等整个应用开发完成。原型延期时暂停扩展，保留当前成果与未完成清单。
- 真实模型费用与可用性由使用者根据自己的服务确认；无密钥不阻塞 D0、A 的开发和规则闭环。
- 对外契约已固定；更改前写出影响，由双方确认并同步调用方。普通模块内部代码选择自行完成，不逐条拆任务和审批。

## 3. A 可以直接使用的任务

```text
我是成员 A，请先读取 README、根 AGENTS.md、frontend/AGENTS.md、backend/AGENTS.md、docs/requirements.md、docs/api.md、docs/architecture.md，检查工作区与已有代码。

我的模块是行程编辑与管理，包含自己的前后端和测试。我同时负责前端工程、公共 TypeScript 类型、统一 HTTP 客户端与 App.vue，使用 Vue 3、TypeScript、Vite、Element Plus、pnpm。不要替 B 重建后端公共模型或规划模块。

先完成属于我的 D0；若 B 的公共模型及景点出口已存在，再完整实现 D1 行程模块：草案编辑、后端统一校验和门票计算、确定规则推荐、确认保存、列表/详情/删除、保存快照，以及相应前端和关键检查。使用约定函数和 API。前置未合入时可以用测试替身验证自己的接口，不另写生产景点服务。

请保留已约定字段和 B 的文件，修改公共契约前说明影响。保存前再次校验，后端费用为准；前端调整期间或校验失败禁止保存，避免过期响应覆盖新编辑。JSON 保存仅面向本地单进程，保证读改写和原子替换，文件损坏不覆盖。

先交付可检查的 D0，再完成我的完整业务模块。检查真实依赖和脚本后运行相关构建/测试，报告实际结果、待对接点和未完成项；不要开发 B 的 Agent、账号后台、数据库或额外功能。推送、PR 和合并按本次用户授权处理。
```

## 4. B 可以直接使用的任务

```text
我是成员 B，请先读取 README、根 AGENTS.md、frontend/AGENTS.md、backend/AGENTS.md、docs/requirements.md、docs/api.md、docs/architecture.md，检查工作区与已有代码。

我的模块是景点与智能规划，包含自己的前后端和测试。我负责后端工程、公共 Pydantic 模型、配置、错误映射和 FastAPI 入口；使用 Python 3.13、FastAPI、Pydantic 2、uv。Agent 用 LangChain create_agent，工具仅一个 search_attractions(city)，不要手写复杂 LangGraph、多 Agent 或长期记忆。

先完成属于我的 D0：公共模型与错误、配置读取、健康接口、示例景点和查询/lookup 出口，并记录可执行的启动和检查命令。D0 后完整实施我的 D1：规划组件、需求输入与景点浏览、生成入口、单 Agent 调用和错误处理。依赖及 SDK 选择以官方文档和实际服务兼容验证为准，锁定真实可用版本。

生成入口两种模式统一使用 A 的规则与校验服务；A 未合入时用测试替身验证边界，不另写生产费用计算。工具参数必须是本次城市；最终输出为分日 ID，校验只使用本次工具返回集合。每请求最多一次工具执行、两次模型调用，关闭隐式自动重试并实施总超时。失败按 API 返回，不能静默降级成规则并冒充 Agent。

前端规划组件按约定事件输出标准草案，由 A 接入页面；保持 A 的行程模块与公共前端文件。先交付 D0 再做完整模块，运行适用测试与真实模型联调并区分报告；没有密钥时完成离线测试并说明待联调，不伪造成功。推送、PR 和合并按本次用户授权处理。
```
